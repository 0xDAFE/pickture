# Optimistic Local Write Queue and Three-Way Snapshot Conflict Detection

Because Pickture's primary workflow targets network-attached storage (SMB/NAS via Files.app security-scoped bookmarks) over high-latency or unreliable mobile connections, writing directly to remote `.xmp` sidecars on each keystroke or swipe would block the UI or drop edits. Instead, Pickture applies `CurationMetadata` changes optimistically to a local persistent cache (`PendingWrite`) and flushes them asynchronously in the background. When Pickture reads or writes a `Sidecar`, it records a `BaseSnapshot` (parsed `CurationMetadata` + file modification timestamp/hash). Before flushing a pending edit (or on folder refresh), Pickture compares the current on-disk `Sidecar` against the `BaseSnapshot`; if the remote sidecar changed externally and its `CurationMetadata` diverges from both the `BaseSnapshot` and the pending local state, the `MediaItem` enters the `Conflicted` `SyncState` (`MetadataConflict`) for interactive diff resolution rather than silently overwriting external desktop edits.
