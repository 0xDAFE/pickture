# Durable SQLite MetadataSyncStore and Off-MainActor Storage Pipelines

To eliminate main-thread serialization freezes and flash memory wear during high-speed culling, Pickture replaces its monolithic JSON sync journal (`sync-journal.json`) with an SQLite database (`sync-store.sqlite` in Application Support) utilizing WAL mode and single-row ACID transactions. `MetadataSyncStore` and `MediaCache` are isolated as dedicated background actors, decoupling all disk I/O, SQLite operations, and LRU evictions from `@MainActor`, while `@Observable CullingSession` maintains lightweight, synchronous in-memory state mirrors to guarantee zero-I/O SwiftUI view evaluation.

Container-embedded preview extraction in `RAWPreviewExtractor` enforces a lean, two-phase I/O strategy: a 128 KB upfront header buffer covers initial IFD0/EXIF structures across local and network storage without stalling slow connections (such as 512 kbit/s links), while any out-of-bounds IFD tables (e.g. in Sony ARW or Nikon NEF) trigger small, targeted range-reads (~100–500 bytes) rather than downloading multi-hundred-kilobyte gaps. Remote `.xmp` write flushes execute off `@MainActor` with volume-aware serialization (1-worker concurrency for `NetworkShare`) to prevent SMB lock contention, and EXIF date parsing utilizes cached Foundation formatters and `Date.ISO8601FormatStyle` to eliminate per-file heap allocation churn.
